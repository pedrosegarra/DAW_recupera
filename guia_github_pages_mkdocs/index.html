    Publicar material con GitHub Pages y MkDocs

    Guía paso a paso para crear un sitio web de documentación a partir de archivos Markdown y publicarlo gratuitamente en GitHub Pages usando MkDocs.

    Requisitos previos

    • Cuenta en github.com
    • Ubuntu / Linux Mint (u otra distro Debian/Ubuntu)
    • Acceso a terminal
    • Git instalado (sudo apt install git)

    1. Crear el repositorio en GitHub

    1. Entra en github.com e inicia sesión.
    2. Haz clic en New repository (botón verde, arriba a la derecha).
    3. Rellena los datos:
    4. Repository name: nombre del proyecto (ej. DAW_recupera)
    5. Visibility: Public ← obligatorio para GitHub Pages gratuito
    6. Deja el resto sin marcar (sin README, sin .gitignore)
    7. Haz clic en Create repository.

    2. Configurar Git en local (solo la primera vez)

    git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"

    3. Generar clave SSH y añadirla a GitHub

    La clave SSH permite autenticarte con GitHub sin escribir contraseña.

    3.1 Generar la clave

    ssh-keygen -t ed25519 -C "tu@email.com"

    Pulsa Enter a todo (sin passphrase si no quieres escribir contraseña cada vez).

    3.2 Mostrar la clave pública

    cat ~/.ssh/id_ed25519.pub

    Copia toda la línea que empieza por ssh-ed25519 AAAA...

    3.3 Añadir la clave a GitHub

    1. Ve a github.com → tu avatar (arriba derecha) → Settings
    2. En el menú izquierdo: SSH and GPG keys
    3. Haz clic en New SSH key
    4. Pon un título descriptivo (ej. portatil-clase) y pega la clave
    5. Haz clic en Add SSH key

    3.4 Verificar la conexión

    ssh -T git@github.com

    Debe responder:

    Hi tu-usuario! You've successfully authenticated...

    4. Instalar MkDocs con pipx

    pipx instala herramientas Python en entornos aislados, sin conflictos con el sistema.

    4.1 Instalar pipx

    sudo apt install pipx
pipx ensurepath
source ~/.bashrc

    4.2 Instalar MkDocs y el tema Material

    pipx install mkdocs
pipx inject mkdocs mkdocs-material

    4.3 Verificar la instalación

    mkdocs --version

    Debe mostrar algo como: mkdocs, version 1.6.1

    5. Clonar el repositorio e inicializar MkDocs

    # Clona el repositorio vacío
git clone git@github.com:tu-usuario/nombre-repo.git

# Entra en la carpeta
cd nombre-repo

# Inicializa la estructura de MkDocs
mkdocs new .

    Esto crea:

    nombre-repo/
├── mkdocs.yml       ← configuración del sitio
└── docs/
    └── index.md     ← página principal

    6. Configurar mkdocs.yml

    Abre el archivo con un editor:

    nano mkdocs.yml

    Reemplaza el contenido por:

    site_name: Nombre de tu sitio
site_url: https://tu-usuario.github.io/nombre-repo
theme:
  name: material
  language: es

nav:
  - Inicio: index.md
  - Tema 1: tema1.md
  - Tema 2: tema2.md

    Guarda con Ctrl+O, Enter, Ctrl+X.

    7. Añadir contenido en docs/

    Todo el contenido del sitio va en la carpeta docs/ como archivos .md (Markdown).

    docs/
├── index.md        ← página de inicio
├── tema1.md
├── tema2.md
└── assets/
    └── ejercicio.pdf

    Ejemplo de archivo Markdown

    # Tema 1: Introducción

Contenido del tema...

## Apartado 1.1

Texto aquí.

[Descargar ejercicio](assets/ejercicio.pdf)

    8. Previsualizar en local

    Antes de publicar, puedes ver el resultado en tu navegador:

    mkdocs serve

    Abre http://127.0.0.1:8000 en el navegador.

    Cada vez que guardes un archivo .md, la página se actualiza automáticamente.

    Para parar el servidor: Ctrl+C

    9. Publicar en GitHub Pages

    mkdocs gh-deploy

    Este comando:

    1. Construye el sitio HTML
    2. Crea automáticamente la rama gh-pages en GitHub
    3. Sube todo

    Tu sitio estará disponible en:

    https://tu-usuario.github.io/nombre-repo

    La primera vez puede tardar 1-2 minutos en estar disponible.

    10. Flujo habitual para actualizar contenido

    # 1. Edita o añade archivos en docs/
nano docs/tema3.md

# 2. Publica los cambios
mkdocs gh-deploy

    No es necesario hacer git add ni git commit manualmente — gh-deploy lo gestiona todo.

    Resumen de comandos

    Comando Qué hace
    mkdocs new . Inicializa estructura MkDocs en el directorio actual
    mkdocs serve Lanza servidor local de previsualización
    mkdocs gh-deploy Publica el sitio en GitHub Pages
    ssh -T git@github.com Verifica la conexión SSH con GitHub
    pipx inject mkdocs mkdocs-material Añade el tema Material a MkDocs

    Solución de problemas frecuentes

    mkdocs: command not found → Ejecuta source ~/.bashrc o abre una nueva terminal.

    git@github.com: Permission denied (publickey) → La clave SSH no está añadida a GitHub. Repite el paso 3.

    Permission denied al clonar → Estás en una carpeta sin permisos de escritura. Cámbiate a tu home: cd ~

    El sitio no aparece tras gh-deploy → Espera 1-2 minutos y recarga. Si persiste, comprueba en el repo de GitHub → Settings → Pages que la fuente es la rama gh-pages.
