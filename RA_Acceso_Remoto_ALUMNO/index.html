    1. Introducción

    En el despliegue de aplicaciones web es imprescindible transferir ficheros entre la máquina de desarrollo y el servidor de producción. Históricamente FTP fue el estándar, pero sus deficiencias de seguridad han impulsado la adopción de alternativas cifradas.

    Comparativa de protocolos

    Protocolo Puerto Cifrado Autenticación Uso recomendado
    FTP 21 / 20 (datos) ❌ No Usuario/contraseña en claro Redes internas aisladas
    FTPS 21 (explícito) / 990 (implícito) ✅ TLS/SSL Certificado + usuario Legado con cifrado
    SFTP 22 ✅ SSH completo Clave pública / contraseña Producción general
    SCP 22 ✅ SSH completo Clave pública / contraseña Copias puntuales
    rsync 22 (sobre SSH) ✅ SSH opcional Clave pública / contraseña Sincronización incremental

    2. FTP — File Transfer Protocol

    2.1 Arquitectura y funcionamiento

    FTP (RFC 959) separa el canal de control (puerto 21) del canal de datos. Hay dos modos:

    • Modo activo: el servidor inicia la conexión de datos hacia el cliente (puerto 20). Problemático con NAT y firewalls.
    • Modo pasivo (PASV): el cliente inicia la conexión de datos hacia un puerto alto del servidor. Necesario en entornos modernos.

    2.2 Instalación y configuración de vsftpd

    # Instalación
sudo apt update && sudo apt install vsftpd -y

# Backup de la configuración
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.bak

    Parámetros clave en /etc/vsftpd.conf:

    anonymous_enable=NO        # Deshabilitar acceso anónimo
local_enable=YES           # Permitir usuarios locales
write_enable=YES           # Permitir escritura
chroot_local_user=YES      # Enjaular usuarios en su home
allow_writeable_chroot=YES # Necesario si el home es editable
pasv_enable=YES            # Modo pasivo
pasv_min_port=40000        # Rango de puertos pasivos
pasv_max_port=50000
pasv_address=<IP_PUBLICA>  # IP pública del servidor

    sudo systemctl restart vsftpd
sudo systemctl enable vsftpd
sudo ufw allow 21/tcp
sudo ufw allow 40000:50000/tcp

    2.3 Comandos FTP

    Comando Descripción
    ftp <host> Conectar al servidor
    ls / dir Listar directorio remoto
    get <fichero> Descargar fichero
    put <fichero> Subir fichero
    mget / mput Transferencia múltiple
    binary Modo binario (imágenes, ejecutables)
    passive Alternar modo pasivo
    bye / quit Cerrar sesión

    ⚠️ Limitación: FTP transmite usuario, contraseña y datos en texto plano. Nunca usar sobre redes no confiables sin cifrado adicional.

    3. FTPS — FTP sobre TLS

    3.1 Conceptos

    FTPS (RFC 4217) añade cifrado TLS al protocolo FTP. Dos variantes:

    • FTPS explícito (FTPES): la conexión empieza como FTP normal y se negocia TLS con AUTH TLS. Puerto 21.
    • FTPS implícito: TLS se establece desde el inicio. Puerto 990. Considerado obsoleto.

    3.2 Configuración de vsftpd con TLS

    # Generar certificado autofirmado
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/vsftpd.key \
  -out /etc/ssl/certs/vsftpd.crt

    Añadir a /etc/vsftpd.conf:

    ssl_enable=YES
force_local_logins_ssl=YES
force_local_data_ssl=YES
ssl_tlsv1_2=YES
ssl_sslv2=NO
ssl_sslv3=NO
rsa_cert_file=/etc/ssl/certs/vsftpd.crt
rsa_private_key_file=/etc/ssl/private/vsftpd.key

    4. SFTP — SSH File Transfer Protocol

    4.1 Qué es SFTP

    SFTP no es FTP sobre SSH. Es un protocolo completamente diferente (parte del estándar SSH-2) que aprovecha la conexión SSH para ofrecer una interfaz de sistema de ficheros remoto. Todo el tráfico viaja cifrado por el canal SSH (puerto 22).

    💡 Un servidor SSH (openssh-server) ya incluye el subsistema SFTP por defecto.

    4.2 Instalación del servidor SSH

    sudo apt install openssh-server -y
sudo systemctl enable ssh
sudo systemctl start ssh

    4.3 Configuración de usuario solo-SFTP con chroot

    Añadir al final de /etc/ssh/sshd_config:

    Match User sftp_user
    ChrootDirectory /var/www/html
    ForceCommand internal-sftp
    AllowTcpForwarding no
    X11Forwarding no

    # El directorio raíz del chroot DEBE pertenecer a root
sudo chown root:root /var/www/html
sudo chmod 755 /var/www/html
sudo systemctl restart ssh

    4.4 Autenticación por clave pública

    # En el cliente: generar par de claves
ssh-keygen -t ed25519 -C "deploy@empresa.com"

# Copiar clave pública al servidor
ssh-copy-id -i ~/.ssh/id_ed25519.pub usuario@servidor

# Verificar
ssh -i ~/.ssh/id_ed25519 usuario@servidor

    4.5 Comandos SFTP interactivos

    Comando Descripción
    sftp usuario@host Conectar
    ls / lls Listar remoto / local
    cd / lcd Cambiar directorio remoto / local
    get <fichero> Descargar
    put <fichero> Subir
    mget *.html Subir múltiples ficheros
    mkdir / rmdir Crear / eliminar directorio remoto
    chmod 644 fichero Cambiar permisos en remoto
    exit / bye Cerrar sesión

    4.6 SFTP no interactivo (scripts)

    # Subir un fichero en modo batch
sftp -b - usuario@servidor <<EOF
put /local/app.tar.gz /var/www/html/app.tar.gz
EOF

# Con clave específica
sftp -i ~/.ssh/id_ed25519 -b comandos.txt usuario@servidor

    5. SCP — Secure Copy Protocol

    5.1 Conceptos

    SCP usa SSH para transferir ficheros de forma cifrada. Su sintaxis recuerda al comando cp. Es ideal para copias puntuales; para sincronización incremental, rsync es superior.

    ⚠️ OpenSSH deprecó el protocolo SCP original en 2022. Las versiones modernas usan SFTP por debajo, pero la sintaxis del comando scp sigue siendo válida.

    5.2 Ejemplos

    # Fichero local → servidor
scp fichero.txt usuario@servidor:/ruta/destino/

# Directorio completo (recursivo)
scp -r ./dist/ usuario@servidor:/var/www/html/

# Con clave específica y puerto no estándar
scp -i ~/.ssh/id_ed25519 -P 2222 app.zip usuario@servidor:/tmp/

# Fichero del servidor → local
scp usuario@servidor:/var/log/nginx/error.log ./logs/

# Entre dos servidores remotos
scp usuario1@origen:/ruta/fich usuario2@destino:/ruta/

    6. rsync — Sincronización incremental

    6.1 Qué es rsync

    rsync transfiere solo las diferencias entre ficheros (algoritmo delta). Puede funcionar sobre SSH (recomendado), protocolo propio o localmente.

    • Transferencia incremental: solo transfiere bloques modificados.
    • Preserva permisos, propietarios, timestamps y enlaces simbólicos.
    • Admite exclusiones, filtros y modo dry-run (simulación).
    • Base de muchas herramientas de despliegue modernas.

    6.2 Opciones clave

    Opción Descripción
    -a (--archive) Modo archivo: preserva permisos, propietario, timestamps, links
    -v (--verbose) Muestra los ficheros transferidos
    -z (--compress) Comprime durante la transferencia
    --delete Borra en destino los ficheros que no existen en origen
    --exclude='patrón' Excluye ficheros/directorios
    --dry-run (-n) Simula sin ejecutar
    -e 'ssh -p 2222' Usa SSH con puerto personalizado
    --progress Muestra progreso de cada fichero

    6.3 Ejemplos de uso

    # Sincronizar directorio local con servidor
rsync -avz ./dist/ usuario@servidor:/var/www/html/

# Con eliminación de ficheros obsoletos
rsync -avz --delete ./dist/ usuario@servidor:/var/www/html/

# Excluir node_modules y .git
rsync -avz --exclude='node_modules' --exclude='.git' ./ usuario@servidor:/app/

# Simular antes de ejecutar (recomendado antes de --delete)
rsync -avzn --delete ./dist/ usuario@servidor:/var/www/html/

# Con clave específica y puerto
rsync -avz -e 'ssh -i ~/.ssh/id_ed25519 -p 2222' ./dist/ usuario@servidor:/var/www/html/

    7. Automatización con Makefile

    7.1 Por qué Makefile en despliegue

    Make permite definir tareas (targets) y sus dependencias. En despliegue web, un Makefile centraliza todos los comandos, evita errores de escritura manual y documenta el proceso de forma reproducible.

    7.2 Makefile completo de despliegue

    # Makefile para despliegue de aplicación web
# Uso: make <target>

# ── Configuración ────────────────────────────────────────────
SERVER      := usuario@servidor.ejemplo.com
REMOTE_DIR  := /var/www/html
LOCAL_DIR   := ./dist
SSH_KEY     := ~/.ssh/id_ed25519
SSH_PORT    := 22
BACKUP_DIR  := /backups/web

SSH         := ssh -i $(SSH_KEY) -p $(SSH_PORT)
RSYNC_CMD   := rsync -avz -e 'ssh -i $(SSH_KEY) -p $(SSH_PORT)'

# ── Targets ──────────────────────────────────────────────────
.PHONY: all check backup deploy sync rollback clean info

all: info

info:
    @echo 'Targets disponibles:'
    @echo '  make deploy   - Despliega con rsync (incremental)'
    @echo '  make sync     - Sincroniza y elimina obsoletos'
    @echo '  make backup   - Crea backup en servidor'
    @echo '  make rollback - Restaura último backup'
    @echo '  make check    - Comprueba conectividad SSH'
    @echo '  make clean    - Limpia dist/ local'

check:
    @echo 'Comprobando conexión SSH...'
    $(SSH) $(SERVER) 'echo OK: conexión establecida'

backup:
    @echo 'Creando backup en servidor...'
    $(SSH) $(SERVER) 'cp -r $(REMOTE_DIR) $(BACKUP_DIR)/backup_$(shell date +%Y%m%d_%H%M%S)'
    @echo 'Backup completado.'

deploy: check
    @echo 'Desplegando $(LOCAL_DIR) → $(SERVER):$(REMOTE_DIR)'
    $(RSYNC_CMD) $(LOCAL_DIR)/ $(SERVER):$(REMOTE_DIR)/
    @echo 'Despliegue completado.'

sync: check
    @echo 'Sincronizando con eliminación de obsoletos...'
    $(RSYNC_CMD) --delete --exclude='.git' --exclude='node_modules' \
      $(LOCAL_DIR)/ $(SERVER):$(REMOTE_DIR)/
    @echo 'Sincronización completada.'

rollback:
    @echo 'Restaurando último backup...'
    $(SSH) $(SERVER) 'LAST=$$(ls -td $(BACKUP_DIR)/backup_* | head -1); \
      rm -rf $(REMOTE_DIR)/*; cp -r $$LAST/. $(REMOTE_DIR)/'
    @echo 'Rollback completado.'

clean:
    @echo 'Limpiando directorio local dist/'
    rm -rf $(LOCAL_DIR)/*

    7.3 Resumen de targets

    Comando Acción
    make check Verifica que la conexión SSH funciona
    make backup Hace backup del servidor
    make deploy Despliega incrementalmente (rsync)
    make sync Despliega y elimina ficheros obsoletos
    make rollback Restaura el último backup
    make clean Limpia el directorio local dist/
    make info Muestra la ayuda de targets disponibles

    💡 Buena práctica: ejecuta siempre make backup antes de make sync en producción. El flag --delete puede eliminar ficheros que no estén en el repositorio local.

    8. Herramientas y flujos modernos

    8.1 FileZilla (cliente gráfico)

    Cliente FTP/SFTP/FTPS más popular. Soporta gestión de favoritos, transferencias en cola, comparación de directorios y edición remota directa.

    sudo apt install filezilla -y
# Configurar: Archivo → Gestor de sitios → Nuevo sitio
# Protocolo: SFTP | Puerto: 22 | Autenticación: Archivo de claves

    8.2 lftp (cliente avanzado por CLI)

    Soporta FTP, FTPS, SFTP y ofrece transferencias en paralelo, mirror (sincronización) y scripting avanzado.

    sudo apt install lftp -y

# Sincronizar directorio completo con SFTP
lftp -e 'mirror -R ./dist/ /var/www/html/; bye' sftp://usuario@servidor

# Con autenticación por clave
lftp -u usuario, sftp://servidor <<EOF
set sftp:connect-program 'ssh -i ~/.ssh/id_ed25519'
mirror -R ./dist/ /var/www/html/
bye
EOF

    8.3 Integración con CI/CD (GitHub Actions)

    # .github/workflows/deploy.yml
name: Deploy to production

on:
  push:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Deploy via rsync
        uses: burnett01/rsync-deployments@7.0.1
        with:
          switches: -avzr --delete
          path: dist/
          remote_path: /var/www/html/
          remote_host: ${{ secrets.REMOTE_HOST }}
          remote_user: ${{ secrets.REMOTE_USER }}
          remote_key: ${{ secrets.SSH_KEY }}

    8.4 Comparativa de herramientas

    Herramienta Tipo Protocolos Puntos fuertes
    vsftpd Servidor FTP, FTPS Ligero, muy configurable
    openssh-server Servidor SFTP, SCP, SSH Incluido en Ubuntu, cifrado completo
    FileZilla Cliente GUI FTP, FTPS, SFTP Intuitivo, comparación de directorios
    lftp Cliente CLI FTP, FTPS, SFTP, HTTP Mirror, paralelismo, scripting
    rsync Sincronización Local / SSH Incremental, delta, muy eficiente
    Make Automatización Cualquiera Tareas declarativas, reproducible
    GitHub Actions CI/CD SSH/rsync Integrado con repositorio, gratuito

    9. Ejercicios resueltos

    ER-01 — Instalar y configurar vsftpd en modo pasivo

    Enunciado: El servidor tiene IP 192.168.1.50. Instala vsftpd, crea el usuario ftpweb y configura el servidor en modo pasivo con rango de puertos 40000-40100.

    Solución:

    # 1. Instalar vsftpd
sudo apt update && sudo apt install vsftpd -y

# 2. Crear usuario confinado
sudo adduser ftpweb --shell /usr/sbin/nologin
sudo mkdir -p /home/ftpweb/web
sudo chown ftpweb:ftpweb /home/ftpweb/web

# 3. Configurar /etc/vsftpd.conf
anonymous_enable=NO
local_enable=YES
write_enable=YES
chroot_local_user=YES
allow_writeable_chroot=YES
pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40100
pasv_address=192.168.1.50
userlist_enable=YES
userlist_file=/etc/vsftpd.userlist
userlist_deny=NO

# 4. Lista blanca y reinicio
echo 'ftpweb' | sudo tee /etc/vsftpd.userlist
sudo systemctl restart vsftpd
sudo ufw allow 21/tcp && sudo ufw allow 40000:40100/tcp

# 5. Verificar desde el cliente
ftp 192.168.1.50
# Introducir: ftpweb / <contraseña>
ftp> passive
ftp> ls

    ER-02 — Configurar SFTP con chroot y clave pública

    Enunciado: Configura el servidor SSH para que el usuario deplower solo pueda acceder por SFTP, confinado en /var/www/html, autenticándose únicamente con clave pública.

    Solución:

    # 1. Crear usuario sin shell interactivo
sudo adduser deplower --shell /usr/sbin/nologin

# 2. Preparar directorios (el chroot DEBE ser propiedad de root)
sudo chown root:root /var/www/html
sudo chmod 755 /var/www/html
sudo mkdir -p /var/www/html/uploads
sudo chown deplower:deplower /var/www/html/uploads

# 3. Añadir al final de /etc/ssh/sshd_config
Match User deplower
    ChrootDirectory /var/www/html
    ForceCommand internal-sftp
    AllowTcpForwarding no
    PasswordAuthentication no

# 4. Generar clave en el cliente y copiarla
ssh-keygen -t ed25519 -C 'deplower@deploy'
# Copiar manualmente la clave pública al servidor:
sudo mkdir -p /home/deplower/.ssh
sudo chmod 700 /home/deplower/.ssh
# Pegar contenido de id_ed25519.pub en /home/deplower/.ssh/authorized_keys
sudo chmod 600 /home/deplower/.ssh/authorized_keys
sudo chown -R deplower:deplower /home/deplower/.ssh

# 5. Reiniciar SSH y verificar
sudo systemctl restart ssh
sftp -i ~/.ssh/id_ed25519 deplower@servidor

    ⚠️ El directorio de chroot debe pertenecer a root y no puede ser escribible por el usuario. Por eso creamos un subdirectorio uploads con permisos del usuario.

    ER-03 — Despliegue con rsync y Makefile

    Enunciado: Crear un Makefile que despliegue ./dist en /var/www/html del servidor 10.0.0.5 usando rsync sobre SSH, con backup previo automático.

    Solución:

    SERVER     := deploy@10.0.0.5
REMOTE     := /var/www/html
LOCAL      := ./dist
SSH_KEY    := ~/.ssh/id_ed25519
BACKUP     := /backups/$(shell date +%Y%m%d_%H%M%S)

.PHONY: deploy backup

backup:
    ssh -i $(SSH_KEY) $(SERVER) 'cp -r $(REMOTE) $(BACKUP)'
    @echo 'Backup creado en $(BACKUP)'

deploy: backup
    rsync -avz --delete -e 'ssh -i $(SSH_KEY)' \
      $(LOCAL)/ $(SERVER):$(REMOTE)/
    @echo 'Despliegue OK'

    Ejecución y salida esperada:

    $ make deploy
ssh ... 'cp -r /var/www/html /backups/20250115_093045'
Backup creado en /backups/20250115_093045
sending incremental file list
index.html
sent 15,234 bytes  received 235 bytes ...
Despliegue OK

    10. Prácticas

    Entorno: Los alumnos trabajan en parejas. Una máquina actúa como servidor y la otra como cliente. Ambas en la misma red local del aula.

    PRÁCTICA 1 — FTP con vsftpd (60 min)

    Objetivo: Instalar, configurar y probar vsftpd en modo pasivo. Comprender las limitaciones de seguridad del protocolo.

    Materiales: 2 máquinas Ubuntu · acceso sudo · Wireshark

    Tareas:

    1. Instala vsftpd en la máquina servidor.
    2. Crea el usuario ftpweb y configura vsftpd en modo pasivo con rango 41000-41100.
    3. Desde el cliente, conéctate con ftp y sube un fichero index.html.
    4. Abre Wireshark en el servidor y captura el tráfico FTP. ¿Puedes ver las credenciales?
    5. Documenta la configuración y adjunta una captura de pantalla de la sesión activa.

    🔍 Reflexión: ¿Qué datos habrías expuesto si esta conexión fuera sobre Internet? ¿Cómo lo solucionarías?

    PRÁCTICA 2 — SFTP con clave pública (90 min)

    Objetivo: Configurar SFTP seguro con autenticación por clave pública y jaula chroot.

    Tareas:

    1. Instala openssh-server en el servidor (si no está).
    2. Genera un par de claves ed25519 en el cliente.
    3. Crea el usuario deplower en el servidor y configura la clave pública.
    4. Añade la directiva Match User en sshd_config para confinar al usuario con ChrootDirectory.
    5. Desde el cliente, conecta por SFTP y sube el proyecto web al directorio remoto.
    6. Verifica que deplower no puede conectarse por SSH interactivo.
    7. Comprueba con Wireshark que el tráfico está cifrado (no se ven credenciales).

    💡 Reto opcional: configura un segundo usuario sftp_ro con permisos de solo lectura sobre el mismo directorio.

    PRÁCTICA 3 — rsync + Makefile de despliegue (90 min)

    Objetivo: Construir un flujo de despliegue profesional usando rsync sobre SSH y un Makefile.

    Escenario: El equipo ha desarrollado una web estática. Hay que desplegarla en el servidor con: - Transferencia incremental (rsync) - Backup automático antes de cada despliegue - Posibilidad de rollback al backup anterior - Exclusión de node_modules y .git

    Tareas:

    1. Crea la estructura: src/, dist/, Makefile.
    2. Escribe el Makefile con los targets: check, backup, deploy, sync, rollback, clean.
    3. Prueba make check: debe verificar la conexión SSH sin pedir contraseña.
    4. Prueba make deploy: verifica que solo se transfieren los ficheros modificados.
    5. Modifica un fichero HTML y vuelve a ejecutar make deploy. ¿Cuántos ficheros transfiere rsync?
    6. Simula un error: borra manualmente un fichero en el servidor y ejecuta make rollback.

    📝 Entrega: Makefile comentado + captura de la salida de make deploy mostrando la transferencia incremental.

    PRÁCTICA 4 — FTPS con certificado TLS (60 min)

    Objetivo: Añadir cifrado TLS a vsftpd y comparar el comportamiento con la práctica 1.

    Tareas:

    1. Genera un certificado autofirmado con openssl.
    2. Activa ssl_enable=YES y los parámetros TLS en vsftpd.conf.
    3. Conéctate desde FileZilla configurando FTPS explícito. Acepta el certificado.
    4. Captura el tráfico con Wireshark. Compara con la captura de la práctica 1.
    5. ¿Qué diferencias observas en el tráfico capturado?
